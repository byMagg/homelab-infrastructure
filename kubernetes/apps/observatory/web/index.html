Tres ordenadores pequeños.
Todo esto, en vivo.

Esta página la sirve un cluster de Kubernetes montado en casa con tres Raspberry Pi. No es una maqueta: los datos salen del sistema real mientras lo miras.

No hace falta saber de servidores. Cada bloque trae una explicación sencilla y, si quieres más, un detalle técnico que puedes desplegar.

01

Tres ordenadores

Son tres Raspberry Pi, del tamaño de una tarjeta de crédito. Están siempre encendidas en casa y se reparten el trabajo.

Detalle técnico

k3s v1.37.2 sobre Raspberry Pi OS Lite (Trixie), ARM64. cluster0 es el plano de control; cluster1 y cluster2 son workers. cluster2 tiene 2 GB y un taint para cargas ligeras.

02

Un director de orquesta

Kubernetes decide en qué ordenador vive cada aplicación, la reinicia si se cae y reparte las copias para que siempre haya alguien atendiendo.

Detalle técnico

k3s con flannel, Traefik como Ingress, ServiceLB y local-path. Cada app corre en pods; los Deployments mantienen el número de réplicas deseado.

03

Todo está en un repositorio

La configuración vive en Git, no en las máquinas. Si alguien cambia algo a mano, Argo CD lo devuelve a como está escrito en el repositorio.

Detalle técnico

GitOps con Argo CD v3.6.1: app-of-apps, selfHeal y prune. Las credenciales van cifradas con Sealed Secrets; nada sensible se commitea en claro.

04

Todo se mide

Un sistema apunta cada 30 segundos cómo va todo: temperatura, memoria, visitas, errores. Si algo se sale de lo normal, avisa al móvil.

Detalle técnico

Prometheus v3.5.0 scrapea node-exporter, kubelet, cAdvisor, kube-state-metrics y Traefik. Alertmanager evalúa 7 reglas y notifica por ntfy.sh.

cluster.yaml --

Los tres ordenadores

En simpleKubernetes reparte las aplicaciones entre las tres Raspberry. Si una se pone al 100 % o se reinicia, las copias de las apps pueden seguir atendiendo desde las otras.

Detalle técnico

k3s v1.37.2, un server y dos agents. cluster2 (2 GB) lleva el taint homelab.io/role=light:NoSchedule; solo toleran ese taint las cargas pensadas para él, como node-exporter y el portfolio.

argo.app --

El repositorio manda

En simpleCada aplicación está descrita en un repositorio de Git. Argo CD compara lo que dice Git con lo que hay de verdad en el cluster y corrige la diferencia. Así no hay cambios a mano que se pierdan.

Detalle técnico

Argo CD v3.6.1 con app-of-apps (homelab-root), automated + prune + selfHeal. Image Updater cambia el tag del portfolio cada ~2 min; el app-of-apps ignora ese campo para no revertirlo.
